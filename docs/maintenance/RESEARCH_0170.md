## DeepSeek suggestions: what is supported

- Ollama [thinking documentation](https://github.com/ollama/ollama/blob/main/docs/capabilities/thinking.mdx) and [API types](https://github.com/ollama/ollama/blob/main/api/types.go) describe top-level `think` and `/api/show.thinking` values/default. Boolean false is valid only where explicitly advertised. Some models use named levels; missing metadata is unknown. We neither infer support from a model name nor treat a successful HTTP response alone as proof that thinking stopped internally.
- [Context documentation](https://github.com/ollama/ollama/blob/main/docs/context-length.mdx) describes VRAM-dependent automatic sizing. [FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx) still includes a 4096 default; [server implementation](https://github.com/ollama/ollama/blob/main/server/routes.go) distinguishes automatic defaults from request, model and environment overrides. Thus 8192 is an observation to verify, not a universal model guarantee. Turning off thinking may free output allowance/latency; it does not increase configured context. Leave `num_ctx` unset and record selected loaded-model `/api/ps.context_length` at campaign end. This is one observation, not a claim about every trial or maximum supported context.
- `OLLAMA_MAX_LOADED_MODELS=1` limits resident models, not parallel requests or context directly. `OLLAMA_KEEP_ALIVE=10m` can reduce repeated cold loads while occupying memory longer. See [environment configuration](https://github.com/ollama/ollama/blob/main/envconfig/config.go). These are workload tradeoffs, not universal improvements; this release changes neither server environment nor keep-alive.
- Low temperature is reasonable for agent consistency but does not establish correctness/determinism. Existing agent temperature 0.2 stays. No chat-temperature mode, training, model replacement, 9B switch or personal-profile rewrite is performed. User confirms terminal 9B and app 8B tests were separate; there is no evidence of competing activity to explain timings.

## How effective agents are built

[Anthropic basic workflows](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/basic_workflows.ipynb) distinguish chaining, routing and parallelization and explicitly label examples non-production. [Evaluator-optimizer](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/evaluator_optimizer.ipynb) requires clear criteria and useful feedback. Its illustrative unbounded loop and printed reasoning are not copied: Aigentics uses deterministic artifact checks, one existing bounded correction, finite steps/time, and no raw thinking export.

[OpenAI Agents runner](https://github.com/openai/openai-agents-python/blob/main/docs/running_agents.md) separates tool calls, final outputs, run state and turn limits; [tools documentation](https://github.com/openai/openai-agents-python/blob/main/docs/tools.md) distinguishes strict function schemas, application-owned execution/approval, MCP and deferred tool loading. [Codex app-server](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) provides concrete lifecycle/approval/event separation. Useful principles here: explicit role/task boundaries, typed native calls, authoritative application state, reproducible external checks, bounded feedback, selective context and durable sanitized evidence. An approval dialog alone is not a sandbox. A final model message alone is not verified success.

Our six locals remain independent specialized snapshots on the same chosen model. This release strengthens their shared harness rather than introducing multi-agent orchestration, MCP, new tools or unlimited reset loops. With a small existing registry, progressive discovery would add complexity before a measured need. Memory continues through checked projects/history/notes, not an unreviewed persistent model narrative. No framework replacement is necessary for these corrections.

## Evidence-driven changes

The latest reviewed 0.15 ZIP contains 30 completed trials: 17 passed/13 failed and 25 offline checks passed. Seven passes needed feedback, including operational readback repairs. Output-limit and timeout evidence remains observational; no causal GPU/model claim. One no-op trial reproduced a real completion mismatch: runtime passed read→unchanged-write→final without the required final read; the independent strict grader correctly failed it. New native-runtime regression was red before the fix. Another issue is evaluation specification: Vera's prompt omitted an explicit object wrapper while the grader required one. Root arrays must still fail; publish a clear root/item schema before the run instead of weakening grading or inventing unavailable actual numeric values.

Only structural schemas are given initially, without expected values/constants. No-op completion now proves read→exactly one identical write request→read of unchanged current bytes, with no actual write. Existing one-turn feedback can request missing evidence within the same budgets. Strict grading and approval rules remain.

Measurement v2 retains the 30 scenario IDs but changes prompts/runtime policy and adds four conditional thinking-off trials. This is a new benchmark identity; old scores must not be presented as a controlled improvement. Reference modes explicitly use model default, treatment false. Matched default/off cases have equal output/time allowances; rows record requested mode, advertised values/default and known timings. Unknown/unsupported/non-thinking controls skip four treatments without generation. Matched pair latency deltas require both tasks to pass. Per-pair metadata and budget mismatch prevents eligibility; cross-run observed setting changes prevent paired comparison. There is no fixed-seed/hidden-compute or causal-performance guarantee.

27 offline app checks plus 34 result slots = 61 outcomes. Optional Deep discovery remains 66 trials plus 27 checks. No API generation tests or automatic report upload. Rich ZIP retains safe native timing counters, control metadata, one end-of-campaign context/server observation, initial/final checks and unchanged-file counters; private content remains excluded and retention limits remain bounded.
