## Aigentics Desktop 0.4.0 — model catalogs and useful evidence

- **Test APIs** makes one model-list GET per unique configured connection, without generation prompts or hidden retries. Up to four requests run together; missing keys, HTTP errors, cancellation, empty lists and partial first pages are explicit. Metadata endpoints may count against provider request limits and do not certify generation access or tools.
- **Saved model catalogs** populate dropdowns across restarts, with fetched timestamps and stale warnings. Failed refreshes keep the previous successful catalog until retention removes it. Recognized presets and manually configured compatible profiles are supported; arbitrary variables do not trigger guessed API calls.
- **Local data** shows storage/counts and opens the actual data folder. Retention controls cover age, completed report count and a report/catalog size budget. Backups now obey the age limit plus the existing newest-three cap. Projects and Desktop key files stay in their existing locations.
- **Diagnostics suite 2** runs 14 built-in disposable checks and optionally the actual local Ollama workflow. It retains bounded structural traces, tool-call counts, generation counters, capability source and template fingerprints. No raw template, prompt or model output is added to reports. Same-suite/model comparisons show status/code changes.
- **Sharing** reuses the exact-preview approval flow for health and API reports. Known provider labels/counts can be shared; custom endpoints/profile IDs and full model lists are excluded. Copy preview helps with browser/login errors; browser mode still needs the final Create action on GitHub.
- **Maintenance workspace** documents approved issue evidence, test boundaries, release steps and an easy user feedback loop. Schema 3→4 preserves agents, settings, sessions and diagnostic sharing history; Windows CI tests the actual released 0.3.0 installer upgrade.
