# How you can help the next update

After installing, let Desktop key/model discovery finish.

1. Click **Test APIs** once. It lists models without generation prompts. Review/approve its GitHub report; browser mode needs no token and finishes with **Create** on GitHub.
2. Click **Diagnose** once with the previous model selected. Leave the local-model test enabled for tool-call investigation. Review/share, including the model name if comfortable.
3. Send the two issue links and one sentence about expected/actual behavior. A screenshot of a stuck status helps; identical reruns usually add less evidence.
4. For coding acceptance, use a disposable project and repeatable task. Review diffs and label **Goal met** or **Needs work** based on actual results. Content capture stays optional.

Keep keys in the existing Desktop `.env`/`.env.txt` or OS vault. Never put values in issues, screenshots, chat, agent instructions or source. **Local data** shows/prunes retained records; do not drag database files around.

For a browser error, use Chrome's GitHub login, **Open repository Issues → New issue**, and **Copy preview** to paste the reviewed report. A draft is not a posted issue. Check for an existing issue before retrying an ambiguous direct upload.

Useful feedback: intended task, expected deliverable, actual result checked, report link. Avoid testing every model or collecting large logs before we have a question to answer.
