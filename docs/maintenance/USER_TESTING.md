# How you can help the next update

For 0.5.0, let startup discovery finish, then:

1. Open **Test model** and select the same saved Qwen agent/model as the earlier failure. The local comparison checkbox tests four route/stream combinations with small synthetic requests; it uses no project tools.
2. Run once. Review/share the report, include the model name if comfortable, finish **Create** on GitHub and send the posted issue URL. No GitHub token is needed in browser mode.
3. If a local route passes, select it only through the confirmation button, then run **Diagnose** once to check actual file creation/read-back. Do not label the full workflow fixed from a one-call probe alone.
4. Optionally select a saved cloud agent and explicitly approve its one-request generation probe. Provider charges may apply. This differs from generation-free Test APIs.
5. In **PROJECTS**, open your existing folder once, save a short project brief and inspect a map/excerpt preview. Save the brief before switching projects. Builder/Reviewer templates expose the retrieval tools; existing agents are not rewritten automatically.

Send the issue link plus one sentence describing expected/actual behavior. Use a disposable project for coding tests and label Goal met/Needs work based on actual files. Session-content capture remains optional. Keys stay in the existing Desktop file/vault; do not include their values in feedback.

Local data shows record counts/retention and the app data folder. There is no need to drag database files around. Browser failures can use Open repository Issues→New issue and Copy preview. A draft is not a posted issue; check for an existing issue before retrying an ambiguous direct upload.
